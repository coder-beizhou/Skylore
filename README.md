# 苍穹 · Firmament Reader

一个能安静读完一本书的桌面小说阅读器。

本地、离线、无账号、无广告。TXT 与 EPUB 通吃，排版参数全开放，还有一套可以随时把界面变成工作软件的摸鱼模式。

---

## 为什么是「苍穹」

市面上的阅读器大多在争夺你的注意力——推荐位、签到、书城入口。苍穹反着来：它只做一件事，把一本书排好、显示好，然后把自己藏起来。

三条硬指标：

| 指标 | 含义 |
|---|---|
| **排版可控** | 字体、字号、行距、字距、段距、缩进、边距全部实时可调，改完立刻重排 |
| **沉浸无扰** | 阅读时控件自动淡出；**滚动/翻页时不会再弹出工具栏**，只有点击中部才会唤出；全屏后除了文字什么都没有 |
| **窗口随意收窄** | 最窄可到 **380px**（贴边并排阅读）；极窄时正文边距自动收敛，每行仍有 18 字以上 |
| **秒级隐藏** | 摸鱼模式一键切换，伪装界面 150ms 内呈现 |

## 功能

### 格式支持

- **TXT** —— 自动嗅探编码。中文网文常见的 GBK / GB18030 / UTF-8 / UTF-16 / BIG5 都能正确解码，不出现乱码
- **EPUB** —— 解析 EPUB2 与 EPUB3（container → OPF → spine），提取封面与目录，并**净化正文样式**

> **为什么要净化 EPUB 样式？** 如果保留 EPUB 自带的 CSS，它会覆盖你的字体设置，结果就是「换了字体，有的章节变了、有的没变」。苍穹剥掉所有内联样式与 class，只保留语义标签，让全局排版完全接管。这是「换字体、换背景能全局生效」的唯一前提。

### 章节识别

覆盖中文网文的实际写法：

```
第一章 初入江湖    第1章 测试        第十二回 归来
第三节 转折        第四卷 风起        Chapter 12
序章 / 楔子 / 前言 / 引子 / 尾声 / 后记 / 番外
1    0001    十二、    【标题】
```

没有任何章头的 TXT 会按字数自动切分，保证**任何文件都能读**。

### 阅读模式

- **左右翻页** —— CSS 多列分页，四种动画：平滑位移 / 仿真翻页 / 淡入淡出 / 无
- **上下滑动** —— 连续流，**自动拼接每一章**：滚到章末无缝接上下一章，可以像刷网页一样从第 1 章一路读到最后一章；向上滚也会自动前插上一章
- **自动翻页** —— 按 3–120 秒的间隔自动翻页，翻到章末自动进下一章
- **自动滚动** —— 像提词器一样缓缓向下滑（6–200 px/秒），**跨章不停**，滚到章末自动接续下一章继续滚。鼠标明显移动或手动滚动时暂停，约 4 秒后自动恢复
- **滚轮手感** —— 单次滚动被限制在视口高度的 22% 以内并做缓动，不会一滚就跳过一整段；触控板保留原生手感

两种模式共用同一套渲染管线，切换时**阅读位置按比例连续保持**，不会跳回开头。

### 字体系统

内置 5 款开源字体（SIL OFL 1.1），**全部是硬笔（钢笔/签字笔）风格**，保证任何机器上都有真手写体与圆体可选：

| 字体 | 类型 | 体积 |
|---|---|---|
| 霞鹜文楷 Lite（LXGW WenKai Lite） | 钢笔楷书 | 4.4 MB |
| 站酷小薇（ZCOOL XiaoWei） | 签字笔细楷 | 2.5 MB |
| 志莽行书（Zhi Mang Xing） | 钢笔行书 | 1.9 MB |
| 站酷庆科黄油（ZCOOL QingKe HuangYou） | 硬笔圆体 | 2.4 MB |
| 站酷快乐体（ZCOOL KuaiLe） | 圆体 | 0.7 MB |

> **为什么不收毛笔体？** 毛笔字体（如马善政毛笔楷书、龙藏行草）笔触过粗、字形夸张，用作正文长时间阅读很累。只保留真正能拿来读的硬笔体。
>
> **为什么统一用 woff2？** 用 `fontTools` 从 TTF 转换，体积减少约 60%（霞鹜文楷 11.1MB → 4.4MB），且全部是**单个完整字体文件**而非 unicode-range 分片 —— 分片方案在 `file://` 环境下实测会 `status=loaded` 但渲染仍回退。

系统字体则通过注册表 / fc-list 探测真实安装情况：

- 宋体、新宋体、仿宋、黑体、微软雅黑、等线
- 楷体、华文楷体、幼圆、圆体
- 华文行楷、华文新魏、方正舒体、华文隶书
- 西文：Georgia、Times New Roman、Garamond、Inter、Segoe UI

**未安装的字体在列表里会被标注「未安装」**，不会出现点了没反应却不知道为什么的情况。同时支持拖入 TTF / OTF / TTC / WOFF / WOFF2 自行扩充。

> **为什么不做硬编码字体列表？** 硬编码会在没装该字体的机器上静默回退到默认字体，用户以为换字体功能坏了。探测 + 标注才诚实。

### 主题与皮肤

两者正交，可自由组合：

- **6 套主题** —— 日间 / 米黄 / 护眼绿 / 羊皮纸 / 夜间 / 墨青
- **2 套皮肤** —— 极简（通透留白）/ 拟物（纸感书页、木质书架、皮革面板）
- **12 种背景纹理** —— 纸纹、布纹、点阵、方格、牛皮纸、云纹、竹影、星空、皮革、雪纹、水墨
  全部用 CSS 生成，不占体积

### 摸鱼模式

| 能力 | 实现 |
|---|---|
| **全局老板键** | `Alt+\`` 默认可改。窗口失焦时依然生效 |
| **迷你框** | 只有文字，无选项、无程序边框。可拖动，**左下角 / 右下角都能拖拽调整大小**，点击两侧翻页 |
| **透明迷你框** | 背景**完全透明**，文字直接浮在桌面上（独立透明窗口）。同样可拖动、双角缩放 |
| **四套伪装界面** | Word 会议纪要 / Excel 报表 / VS Code / Outlook 邮件，**每个界面里都能直接读小说** |
| **隐身模式** | 窗口透明度降到 6%，几乎看不见但仍在读 |

> **伪装界面里的小说藏在哪？**
>
> | 界面 | 外壳 | 正文位置 |
> |---|---|---|
> | Word | Win11 标题栏 + Ribbon + 标尺 + 会议纪要抬头 | 文档正文（接着抬头往下排） |
> | Excel | Ribbon + 行列号 + 数据表 + Sheet 标签栏 | 右侧 G/H/I 列的「备注说明」 |
> | VS Code | 标题栏 + 活动栏 + 资源管理器 + minimap + 终端面板 | 打开的 `notes.md` |
> | Outlook | 标题栏 + 文件夹树 + 未读邮件列表 | 右侧阅读窗格（邮件头下方） |
>
> 每个界面**都能翻页与上下滑动**：点两侧翻一屏、滚轮按行滚、`PageUp`/`PageDown`/空格/方向键都可用，
> 滚到章末或章首会自动接续**上一章 / 下一章**（与主阅读器的连续滚动同一套逻辑）。
> 阅读位置与主阅读器双向同步 —— 从伪装界面退出后，回到阅读器接着读。

**退出方式（6 条独立通道，任意一条可用即可退出）：**

| 方式 | 操作 |
|---|---|
| 界面按钮 | 鼠标移到迷你框上，点右上角的 × |
| 退出键 | 按 `Esc`（部分系统上裸 Esc 无法注册，则会自动降级为 `Ctrl+Esc`） |
| 辅助切换键 | `Ctrl+Alt+Q` 在摸鱼与阅读间来回切换 |
| 老板键 | 再按一次老板键切回 |
| 强制恢复 | `Ctrl+Shift+Alt+R`，任何情况下都能退出 |
| 右键 | 在迷你框内点右键直接退出 |

> **为什么要这么多条退出通道？** 最初只做了「老板键」和「双击顶部」两条。但老板键 `Alt+\`` 极易与输入法切换冲突而注册失败；进入摸鱼时窗口故意不抢焦点，导致渲染层的 Esc 处理完全失效。两者叠加就会出现「进得去出不来」。现在用全局 Esc + 固定辅助键 + 可见按钮彻底堵住这个死角。
> 设置页会列出当前**每一条通道的实际可用状态**，老板键注册失败时会明确提示改用什么键退出。

所有伪装界面在启动时就预生成完毕，切换只改 DOM 可见性，不加载任何资源——这是能做到 150ms 内呈现的原因。

## 技术选型说明

| 决策 | 原因 |
|---|---|
| **Electron** | 需要直接扫描本地文件夹、枚举系统字体、注册全局热键——浏览器沙箱做不到 |
| **不用 epub.js** | 它用 iframe 渲染，主题与字体无法统一控制。自研解析让 TXT 与 EPUB 走同一套渲染管线 |
| **无框架、无打包器** | 交互逻辑可控，原生 ES Module 足够；避免构建链成为风险点 |
| **分页用 CSS 多列** | 浏览器原生排版引擎处理换行与断行，比手工测量准确得多 |
| **进度按「章内比例」存** | 字号、窗口、模式变化都不会丢位置。存页码一定跑偏 |

### 已规避的坑

代码里对这些地方有明确注释，都是实际踩过的：

1. **分页重排时机** —— 必须在 `document.fonts.ready` 与图片 `load` 之后重排，否则行高变化导致分页错位、丢字
2. **页边距读取** —— 页边距必须从 CSS 变量读，不能读 computed padding（首次读到的是 0，正文会顶到窗口边缘）
3. **自动滚动步进** —— 必须用浮点累加，`scrollTop++` 会因取整丢精度并产生卡顿
4. **EPUB 自闭合标签** —— OPF 里 `<item/>` 是自闭合的，只匹配成对标签会让 manifest 全部读空
5. **空书架渲染** —— 渲染空态时不能 `clear()` 掉父容器，否则会把书籍网格节点一起删掉，导入第一本书时崩
6. **迷你框窗口尺寸** —— 主窗口的最小尺寸约束会把它钳制住，必须进摸鱼时先解除
7. **颜色分量钳位** —— 分量超过 255 会按字节回绕（259 → 3），白色会变成亮黄
8. **单实例锁** —— 残留进程会让新进程静默退出（看起来像测试通过，其实没跑）
9. **`max-width: 0px` 塌陷** —— 正文最大宽度在「自适应」时值为 `0px`，直接用作 `max-width` 会让容器宽度塌成 0，中文每字独占一行。必须写 `none`
10. **`overflow: hidden` 与 padding** —— padding **不参与裁剪**。用 padding 给分页做边距裁剪时，相邻列会从边距区域露出来（表现为"当前页两侧有别的文字"）。裁剪层必须按 `left/top/width/height` 精确定位
11. **`@import` 位置** —— CSS 规范要求 `@import` 必须在所有其他规则之前，放在 `@font-face` 之后会被**整条忽略**且不报错
12. **`document.fonts.check()` 的假阳性** —— 对**从未注册过**的字体族也返回 `true`（因为会回退到默认字体）。判断字体是否真的加载必须用「不存在的族名」做对照，或检查 `document.fonts` 集合里该族的 `status`
13. **中文字体度量无法区分** —— 中文字体对 CJK 码位一律是 2/2 em 等宽设计，宋体与黑体的汉字宽度**完全相同**（实测都是 360px）。不能用「页数变了没」「宽度变了没」判断字体是否生效，必须看字形或混入拉丁字符测量
